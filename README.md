# rs-10871-demo

Demo for [adobe/react-spectrum#10871](https://github.com/adobe/react-spectrum/pull/10871). [Open on StackBlitz](https://stackblitz.com/github/mangeshraut712/rs-10871-demo).

The left Select uses the unmodified `react-aria-components@1.22.1` package. The right adds an **English-only approximation** of the PR's count-announcement effect in `src/main.jsx`; it is not a build of the upstream patch and does not exercise its localized formatter. Both have five options in two groups, with Cat selected initially.

To compare, focus each Select and press Space. On Apple devices, the right side should add "5 options available." even with Cat focused. Moving focus should not repeat the count; closing and reopening should announce it again. On non-Apple devices, opening with a focused option should not add a count. The helper's log records its calls to the live announcer, not speech actually delivered by a screen reader or announcements generated by the underlying library.

Manual VoiceOver verification in macOS Safari is still required. Browser rendering, automated DOM checks, and a populated live region do not establish what VoiceOver speaks.

The helper skips React Aria's hidden collection-building render, which has no `SelectStateContext`, and mounts its effect only beneath the live Select's state provider. This fixes the blank-preview crash without changing the unpatched baseline or removing the announcement effect.

Run locally:

```sh
npm ci
npm test
npm run build
npm run dev
```

The integration regression test mounts the real app and React Aria collection, checks keyboard opening and focused Cat, verifies no baseline count, checks the patched live region and grouped count, and covers focus changes, reopening, and non-Apple behavior. CI runs this test before building.
